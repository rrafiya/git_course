日常开发的完整循环

改代码 → 看状态 → 加暂存 → 提交 → 推送，五步走完一轮

STEP 1
改代码
编辑 index.html

在工作区里正常修改文件。Git 会自动发现哪些文件变了，不需要你手动标记。

查看
STEP 2
看状态
git status git diff

改之前先看：确认哪些文件被改动、改了什么，避免误提交。

git add
STEP 3
加暂存
git add <文件> git add -A

把要提交的改动放进暂存区。可以只挑一个文件，不必全部提交。

git commit
STEP 4 · 5
提交并推送
git commit -m "..." git push

先在本地存一个版本快照，再上传到 GitHub。这两步是分开的。

最容易搞混的一点：commit 只是把版本存到你本地的 .git 里， GitHub 上还看不到；必须再执行 push 才会同步到远程。
本案例的每次修改都是「先 commit 再 push」，所以 GitHub 上的提交历史和本地完全一致。
