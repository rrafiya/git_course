# 《Git 与 GitHub 从入门到实战》PPT 制作指南

本目录下已经有一个可直接使用的成品：

| 文件 | 说明 |
|---|---|
| **`Git与GitHub从入门到实战.pptx`** | 正式 PPT，22 页，16:9，用 PowerPoint 打开即可 |
| **`预览.html`** | 浏览器预览版（同一个内容与版式，双击即可看） |
| `deck.json` | PPT 的全部文字内容（改这个文件就能改 PPT） |
| `img/` | 12 张图片素材（8 张示意图 + 4 张真实截图） |
| `build_pptx.mjs` | 生成 pptx 的脚本 |
| `preview.mjs` | 生成预览页的脚本 |

想改内容 → 改 `deck.json` → 跑 `node build_pptx.mjs` 和 `node preview.mjs` 即可。

---

## 一、这份 PPT 是怎么做出来的

整条流水线只有三步，**不需要任何第三方库**（不能联网装包时尤其有用）：

```
① 用 HTML/CSS 画素材  →  ② 无头 Chrome 截图成 PNG  →  ③ 生成 pptx
       (示意图/终端图)          (真实截图也走这条路)        (拼装 OOXML)
```

### 第 ① 步：用 HTML + CSS 画示意图

PPT 里的这些图**不是用画图软件画的，而是用 HTML 写的**：

| 素材 | 做法 |
|---|---|
| `02_three_areas.png` | 用 flex 布局排四个圆角卡片 + CSS 三角形箭头 |
| `03_push_pull.png` | 绝对定位放两个仓库卡片，中间用渐变线做 push/pull 箭头 |
| `04_timeline.png` | 左侧一条渐变竖线 + 圆点，右侧逐条列提交 |
| `05_workflow.png` | 五列 flex 布局，每列一个步骤卡片 |
| `06_github_page.png` | 手写 CSS 模仿 GitHub 仓库页（顶栏/文件列表/侧栏） |
| `07_cheatsheet.png` | CSS Grid 两列八张卡片 |
| `08_git_vs_github.png` | 左右双栏对比 + 中间 `≠` |

**为什么用 HTML 画而不是画图软件**：
- 排版用 flex/grid，对齐精确到像素，不会手抖
- 配色用 CSS 变量，改一处全局生效
- 图表内容和真实数据一致（时间线里的 11 次提交是从 `git log` 抄下来的）
- 可随时重新生成，不怕改

### 第 ② 步：用无头 Chrome 把 HTML 渲染成 PNG

```js
// 核心就这几行（通过 Chrome DevTools Protocol）
await send('Emulation.setDeviceMetricsOverride', {
  width: 1400, height: 760, deviceScaleFactor: 2   // 2 倍分辨率，投影不虚
});
await send('Page.navigate', { url: 'file:///…/a2_three_areas.html' });
await sleep(1800);
const r = await send('Page.captureScreenshot', { format: 'png' });
fs.writeFileSync('img/02_three_areas.png', Buffer.from(r.data, 'base64'));
```

`deviceScaleFactor: 2` 是关键 —— 导出的图是 2 倍尺寸，放进 PPT 缩放后依然锐利。

**真实截图走的是同一条路**：把 `index.html`（游戏）加载进来，用
`Input.dispatchKeyEvent` 模拟按键进入游戏、`Page.captureScreenshot` 截图。
所以 PPT 里的游戏画面、GAME OVER 界面、诊断页截屏，**全是真的**。

### 第 ③ 步：生成 pptx

`pptx` 本质就是一个 **ZIP 包 + 一堆 XML**。所以可以完全用代码拼出来：

```
test.pptx
├── [Content_Types].xml        声明每个部件的内容类型
├── _rels/.rels                指向 ppt/presentation.xml
├── docProps/core.xml          标题/作者/时间
├── docProps/app.xml
└── ppt/
    ├── presentation.xml       幻灯片列表 + 画布尺寸
    ├── _rels/presentation.xml.rels
    ├── slideMasters/slideMaster1.xml     母版（背景色、默认字体）
    ├── slideLayouts/slideLayout1.xml     版式（type="blank" 空白版式）
    ├── slides/slide1.xml … slide22.xml   每页的实际内容
    ├── slides/_rels/slideN.xml.rels      每页引用的图片
    └── media/image1.png … image10.png
```

`slide1.xml` 里一个文本形状长这样（有删减）：

```xml
<p:sp>
  <p:nvSpPr><p:cNvPr id="2" name="tb2"/><p:cNvSpPr txBox="1"/><p:nvPr/></p:nvSpPr>
  <p:spPr>
    <a:xfrm><a:off x="838200" y="1600200"/><a:ext cx="9144000" cy="457200"/></a:xfrm>
    <a:prstGeom prst="rect"><a:avLst/></a:prstGeom>
    <a:noFill/>
  </p:spPr>
  <p:txBody>
    <a:bodyPr wrap="square" lIns="0" rIns="0" tIns="0" bIns="0" anchor="t"/>
    <a:lstStyle/>
    <a:p>
      <a:pPr algn="l"><a:buNone/></a:pPr>
      <a:r>
        <a:rPr lang="zh-CN" sz="2800" b="1">
          <a:solidFill><a:srgbClr val="9FE8FF"/></a:solidFill>
          <a:latin typeface="Microsoft YaHei"/>
          <a:ea typeface="Microsoft YaHei"/>
        </a:rPr>
        <a:t>先看本次案例是什么</a:t>
      </a:r>
    </a:p>
  </p:txBody>
</p:sp>
```

几个**容易踩的坑**（我实际踩过的）：

1. **单位是 EMU**，不是像素也不是磅。换算：`1 英寸 = 914400 EMU`。
   16:9 幻灯片 = `12192000 × 6858000` EMU（13.333″ × 7.5″）。
2. **命名空间不能写错**，两个最容易混的：
   - `p:` → `http://schemas.openxmlformats.org/presentationml/2006/main`
   - `a:` → `http://schemas.openxmlformats.org/drawingml/2006/main`
3. **`[Content_Types].xml` 必须覆盖每一个部件**，否则 PowerPoint 报"文件损坏"。
   `.png` 之类要写 `<Default Extension="png" .../>`，`.xml` 部件要写 `<Override .../>`。
4. **每个 `r:id` 必须在对应的 `.rels` 里有定义**，图片还要单独建 `slideN.xml.rels`。
5. **形状 `id` 必须唯一**，且不能和 `spTree` 里的 `id="1"` 冲突。
6. **ZIP 里不要用数据描述符**（general purpose flag 的第 3 位要保持 0），
   文件名要置 UTF-8 标志位（`0x0800`），否则中文名或某些解析器会出错。
7. **没有 `theme1.xml` 也能用** —— 参考真实的"纯色极简"模板后发现，
   只要在母版里直接写死背景色、在每个形状上直接写死字体和颜色，
   就完全不依赖主题。这样能少写一个复杂部件。

### 那怎么验证做出来的文件没问题？

`PowerPoint` 打不开时（见下面"环境限制"），可以程序化校验：

```bash
node validate.mjs "Git与GitHub从入门到实战.pptx"
```

它会逐项检查：ZIP 中央目录、每个条目的 CRC 与解压长度、全部 XML 是否良构、
内容类型是否覆盖所有部件、所有关系目标是否存在、每个 `r:id` 是否有定义、
图片是不是有效 PNG。本次输出：

```
✅ ZIP 中央目录完整（64 个条目）
✅ 全部 64 个条目 CRC 与解压长度校验通过
✅ 全部 54 个 XML 部件良构
✅ 所有部件都有对应的内容类型声明
✅ 全部 60 条关系目标都存在
✅ presentation.xml 的 23 个 r:id 引用全部有效
✅ 22 张幻灯片都有关系文件
✅ 10 个图片均为有效 PNG
```

另外还写了个**版式体检**脚本，用浏览器量出每一页的内容底边，
确认没有文字跑到幻灯片外面：

```

  1   630      614      -16        0  Git 与 GitHub 从入门到实战
  3   630      614      -16        0  先看本次案例是什么
 …
✅ 全部 22 页版式正常，无溢出
```

## 二、环境限制记录（换机器时可能遇到）

| 现象 | 原因 | 解法 |
|---|---|---|
| Chrome 启动失败，`platform_channel.cc: 拒绝访问` | 沙箱禁止创建命名管道，而 Chrome 的 Mojo IPC 依赖它 | 放宽该命令的沙箱权限后再启动 |
| Node 用 `child_process.spawn` 启动浏览器报 `EPERM` | 管道 stdio 被禁止 | 改用 PowerShell 的 `Start-Process` 启动，再用 Node 连 CDP |
| PowerPoint COM 能用，但 `Presentations.Open` 报"文件损坏" | **本机 PowerPoint 打不开任何演示文稿**（连真实 PPTX 也一样） | 改用程序化校验 + HTML 预览页确认版式 |
| PowerShell 脚本里的中文变成乱码 | 脚本文件编码被误判 | 脚本保持纯 ASCII，中文全部放 UTF-8 的 JSON，用 `Get-Content -Encoding UTF8` 读 |

**结论**：`.pptx` 生成这条路在没有 PowerPoint 的机器上依然可行，
只要**把"内容生成"和"渲染校验"解耦** —— 内容用代码生成，
校验用 ZIP/XML 结构检查 + 浏览器版式体检。

## 三、怎么改成你自己的 PPT

1. **换内容**：编辑 `deck.json`。每页是一个对象：

```json
{
  "layout": "content",          // cover | toc | content | image
  "title": "页面标题",
  "image": "04_timeline.png",   // 可选，有图则左文右图
  "lines": [
    "H|小标题（金色加粗）",
    "B|普通要点，支持 **加粗** 和 `代码`",
    "C|命令行代码块",
    "Q|强调引用（绿色左边框）",
    "N|次要说明（灰色小字）"
  ]
}
```

行首前缀就是样式标记：`H`=小标题、`C`=代码、`Q`=引用、`N`=注释、
其它（如 `B|`）或不带前缀=圆点要点。`**文字**` 会变金色加粗，`` `文字` ``
会变青色等宽字体。

2. **换图片**：把 PNG 放进 `img/`，在 `deck.json` 里写文件名即可。
   要自己做示意图，就照 `a2_three_areas.html` 的样子写一个新 HTML，
   再用 `_shot.mjs` 截图。

3. **换配色**：改 `build_pptx.mjs` 顶部的 `C` 对象（十六进制色值）。

4. **重新生成**：

```bash
node build_pptx.mjs     # 生成 pptx
node preview.mjs        # 生成预览页
node validate.mjs "Git与GitHub从入门到实战.pptx"   # 校验
```
