Git 常用命令速查表

本案例实际用到的命令都已标出 ✓

① 创建与获取仓库 起步

git init # 把当前文件夹变成 Git 仓库 ✓ git clone <url> # 把远程仓库复制到本地
✓ 本案例第一步就是在空文件夹执行 git init， 从此这个文件夹的每次改动都能被追踪。

② 查看状态与历史 最常用

git status # 哪些文件改了？✓ git diff # 具体改了什么内容 git log --oneline --graph # 提交历史 ✓
✓ 每次动手前先 git status， 是避免误提交最有效的习惯。

③ 提交改动 核心

git add <文件> # 加入暂存区 ✓ git add -A # 所有改动一起加 ✓ git commit -m "说明" # 提交 ✓ git commit -F 文件 # 从文件读多行说明
提交说明建议用前缀区分类型：feat 新功能 / fix 修 bug / docs 文档 / chore 杂项。本案例 11 次提交全部遵循这个约定。

④ 与 GitHub 同步 协作

git remote add origin <url> # 关联远程 ✓ git push -u origin main # 首次推送 ✓ git push # 之后的推送 ✓ git pull # 拉取远程更新
✓ 首次推送加 -u 建立跟踪关系， 之后直接 git push 即可。

⑤ 撤销与回退 救命

git restore <文件> # 丢弃未暂存的修改 git restore --staged <文件> # 移出暂存区 git revert <hash> # 安全地反向提交 git reset --soft HEAD~1 # 撤销上次提交但保留改动
已推送的提交不要用 reset 改写历史，用 revert 更安全。

⑥ 分支 并行开发

git switch -c 新分支 # 建并切换分支 git switch main # 切回主分支 git merge 分支名 # 合并到当前分支 git branch -vv # 查看分支与跟踪关系 ✓
本案例只有一个 main 分支；多人协作时通常每个功能开一条分支， 通过 Pull Request 合并。

⑦ 排查与对比 定位问题

git ls-remote origin # 远程有哪些分支 ✓ git show HEAD:文件 > 旧版本 # 取某次提交的文件 ✓ git diff HEAD~1 HEAD # 对比两次提交 git rev-parse HEAD # 查看当前提交 hash ✓
✓ 本案例排查显示 bug 时，就用 git show HEAD:index.html 取出旧版本，与新版对比验证修复效果。

⑧ 配置 一次性

git config --global user.name "名字" # ✓ git config --global user.email "邮箱" # ✓ git config --global --list # 查看全部配置 ✓
不配置姓名邮箱，git commit 会直接报错。本案例一开始就是空配置， 提交时才补上。
